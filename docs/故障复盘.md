## 故障复盘1

### 现象
部署完应用后，验证curl -I 127.0.0.1:3000显示Connection refused

### 排查
1. 检查应用是否正常运行：`sudo systemctl status myapp`===>`activating (auto-restart)`，进程 `status=1/FAILURE`
2. 查看日志：`sudo journalctl -u myapp -n 50` ===>得出关键报错：mysql登陆失败`Access denied for user 'appuser'@'localhost' (using password: YES)`
3. 排查mysql服务和登录账户===>无误
4. 排查app.js配置===>发现配置文件中密码不符实际登陆密码
### 原因
应用配置中的 MySQL 密码与数据库实际密码不一致，应用启动即崩溃。
### 处理与验证
修正密码为一致后重启服务，curl返回 200。

## 故障复盘2
### 现象
浏览器访问myblog.example.com返回502错误。
### 排查
1. 追踪myapp.error.log===>111: Connection refused,upstream: "http://127.0.0.1:3001/"：目标端口没有进程在监听
2. 查看服务在哪个端口：`ss -lntp | grep node`===>监听3000端口
3. 检查myapp.conf配置===>发现`proxy_pass http://127.0.0.1:3001`代理端口设置有误
### 原因
页面报错502同时错误日志报错111，代表后端无服务响应。考虑到有可能是服务未开启或者服务端口与nginx反向代理地址不一致，故查看服务端口，发现显示的监听端口与日志中的upstream不一致，故可确定服务端口与nginx反向代理地址不一致。
### 处理与验证
修改代理端口为3000，`sudo nginx -s reload`重载服务。浏览器重新访问链接，成功显示页面。
